# SIGNUM 312 — Novidades.store

Conversion-first single-product funnel for `signum312.novidades.store`.

## Stack

- Next.js App Router
- TypeScript
- Native CSS
- Meta Pixel / GTM hooks
- Native checkout UI
- Server-to-server XPayments PIX integration for BRL

## Local development

```bash
npm install
cp .env.example .env.local
npm run dev
```

## XPayments — BRL / PIX

The browser never receives the XPayments API key.

Flow:

```text
Landing
  -> /checkout?variant=patina&currency=BRL
  -> POST /api/payments/pix
  -> server-side POST https://api.xpayments.digital/api/v1/payments/charge
  -> XPayments S2S PIX
  -> QR Code + Pix Copia e Cola
  -> polling through /api/payments/pix/status
  -> paid confirmation
```

Required production variables:

```text
XPAYMENTS_API_URL=https://api.xpayments.digital/api/v1
XPAYMENTS_API_KEY=<live store API key with payments_write>
```

The production BRL key must belong to **NOVIDADES-BRL**. That Store must be active, use BRL, have `payments_write`, and have active PIX routing/provider configuration.

Payload generated by this app:

```json
{
  "amount": 9990,
  "currency": "BRL",
  "payment_method_types": ["pix"],
  "reference": "SIGNUM312-...",
  "customer": {
    "name": "Customer",
    "email": "customer@example.com",
    "document": "CPF_OR_CNPJ"
  },
  "metadata": {
    "order_id": "SIGNUM312-...",
    "product": "SIGNUM 312",
    "variant": "patina"
  }
}
```

Amounts are calculated on the server from the product catalog. The client cannot submit an arbitrary amount.

## Payment confirmation

XPayments updates the original transaction asynchronously through its PIX provider webhook.

The checkout polls idempotently using the same merchant reference. While pending, XPayments returns the stored PIX. Once the transaction is already succeeded, the API returns `TRANSACTION_ALREADY_PAID`, which this app treats as payment confirmation.

## Second currency

The checkout architecture is ready for a second currency. It is intentionally not exposed until the international payment rail and EUR pricing are confirmed.

Candidate target:

- BRL -> PIX S2S
- EUR -> **NOVIDADES-EURO** via the XPayments international rail to be selected

## Conversion principles

- Product visible immediately
- Ad-to-landing message match
- Pátina, Dourada and Duo offers
- Native checkout with no third-party visual jump before payment
- Sticky purchase CTA
- Real product photo proof section
- No fake scarcity, fake reviews or false countdowns
- Historical story framed as tradition, not fake provenance
- Mobile-first

## Before paid traffic

1. Connect Vercel and `signum312.novidades.store`.
2. Configure a dedicated XPayments live Store/API key.
3. Test PIX creation with low-value controlled order.
4. Confirm webhook -> transaction succeeded -> checkout paid state.
5. Add legal seller identity, contact details and shipping rules.
6. Configure Meta Pixel/GTM and verify events.
7. Replace/augment current product photos with final packshots and packaging.


## XPayments Store topology

- `NOVIDADES-BRL` — BRL / PIX S2S / Brazilian funnel payments.
- `NOVIDADES-EURO` — EUR / international methods for European funnels.

The frontend should never reuse payment credentials from unrelated projects. Each environment receives only the API key for the Store required by that deployment.
